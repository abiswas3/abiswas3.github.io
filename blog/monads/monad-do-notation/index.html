Notes on Chapter 4.4: do-Notation for Monads from Functional Programming in Lean.

Working code: FunctionalProgramming/monad-do.lean

In the previous post we unified bind and pure into a type class. But writing >>= fun x => everywhere is still noisy. do notation is syntactic sugar that the compiler rewrites into >>= calls — making monadic code look imperative.

This is the same do you've been using in IO. Now you know what it actually means.

Which Monad Does do Use?

Every do block needs a monad — because do desugars to bind and pure, and those come from a Monad instance. Lean infers which monad from the return type:

-- Return type is IO Unit → do uses IO's bind and pure
def main : IO Unit := do
  IO.println "Hello"
  let name ← IO.getLine
  IO.println s!"Hi, {name}!"
-- Return type is Option (Nat × Nat) → do uses Option's bind and pure
def findBoth (xs : List Nat) : Option (Nat × Nat) := do
  let first ← xs[0]?    -- if none, Option's bind short-circuits
  let third ← xs[2]?
  pure (first, third)

#eval findBoth [1, 2, 3]  -- some (1, 3)
#eval findBoth [1]         -- none

What if the return type is plain — like Nat or CPU — and not monadic? Then do has no monad to work with. You use Id.run:

-- With do + Id.run:
def mySum (l : Array Nat) : Nat := Id.run do
  let mut out := 0
  for i in l do
    out := out + i
  return out

-- Without do — the for loop becomes foldl, the mutable variable becomes the accumulator:
def mySum' (l : Array Nat) : Nat :=
  go l.toList 0
where
  go : List Nat → Nat → Nat
    | [], out => out
    | i :: rest, out => go rest (out + i)

Both compute the same thing. The do block is just a nicer way to write the recursion. The for loop becomes go, the let mut out becomes the accumulator parameter, and return out becomes the base case.

Aside: what is go and where?

where defines a local function — like a let but written after the main definition. go is just the name we gave it. The same code without where:

def go : List Nat → Nat → Nat
  | [], out => out                    -- empty list: return accumulator
  | i :: rest, out => go rest (out + i) -- add i to accumulator, recurse

def mySum' (l : Array Nat) : Nat := go l.toList 0  -- start with accumulator = 0

You can't mix two monads in one do block. A do block uses exactly one monad, determined by the return type.

Translation Rules

Four rules. The compiler applies them mechanically.

Rule 1 — base case, a single expression. Just strip the do:

do E   →   E

Example: do pure 5 → pure 5

Rule 2 — let with ← (extract from monadic context):

do let x ← E₁       →     E₁ >>= fun x =>
   ...                        do ...

Example:

do let x ← lookupOption xs 0    →    lookupOption xs 0 >>= fun x =>
   pure x                               pure x

Rule 3 — expression statement (returns Unit):

do E₁                →     E₁ >>= fun () =>
   ...                        do ...

Example:

do setState (n + 1)         →    setState (n + 1) >>= fun () =>
   pure n                          pure n

Rule 4 — plain let with := (no monad, just a local binding):

do let x := E₁       →     let x := E₁
   ...                      do ...

Example:

do let y := x + 1       →    let y := x + 1
   pure y                     pure y

That's it. ← means "use bind to extract the value." := means "ordinary let, no binding." A bare expression means "run it, ignore the result."

firstThirdFifthSeventh

Each let x ← ... on the right is rewritten to ... >>= fun x => on the left by Rule 2. The compiler inserts the bind calls for you.

#eval firstThirdFifthSeventh lookupOption [1, 2, 3, 4, 5, 6, 7, 8]
-- some (1, 3, 5, 7)

#eval firstThirdFifthSeventh lookupExcept [1, 2, 3]
-- Except.error "Index 4 not found (maximum is 2)"

mapM

With nested actions — (← E) inside an expression means "bind E and insert the result here." Almost as short as the non-monadic List.map:

def mapM'' [Monad m] (f : α → m β) : List α → m (List β)
  | [] => pure []
  | x :: xs => do
    pure ((← f x) :: (← mapM'' f xs))

Tree Numbering

Note how setState (n + 1) on its own line uses Rule 3 — it's an expression statement returning Unit, so the compiler inserts >>= fun () =>.

With nested actions — extract increment and use (← ...):

def increment : State Nat Nat := do
  let n ← getState
  setState (n + 1)
  pure n

def numberHelper' : BinTree α → State Nat (BinTree (Nat × α))
  | BinTree.leaf => pure BinTree.leaf
  | BinTree.branch left x right => do
    pure (BinTree.branch
      (← numberHelper' left)
      ((← increment), x)
      (← numberHelper' right))

Summary

do notation is not magic — it's four mechanical rewrite rules that convert readable sequential-looking code into >>= chains. The ← means bind. The := means ordinary let. A bare expression means "run it for the side effect."

Every do block you've ever written in IO was doing this. Now you know what's underneath.
