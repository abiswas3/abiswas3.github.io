Monads in FP in Lean

Ari 2026-03-23
basicmonads

Notes on Chapter 4.1: One API, Many Applications from Functional Programming in Lean. See also our companion post on Dan Piponi's monads.

The key idea from the Piponi post: a monad is (m, unit, bind) — a type, an identity, and a way to compose functions whose return types are wrapped in that type. Here the book shows the same pattern across four examples.

Working code: FunctionalProgramming/monad.lean

1. Option: Silent Failure

Option α is either none or some x. List indexing with xs[i]? returns an Option.

Problem

Get the first and third elements of a list. Each access can fail.

Without bind, we match-and-unwrap at every step:

def firstThird (xs : List α) : Option (α × α) :=
  match xs[0]? with
  | none => none
  | some first =>
    match xs[2]? with
    | none => none
    | some third => some (first, third)

#eval firstThird [1, 2]        -- none
#eval firstThird [1, 2, 3, 4]  -- some (1, 3)

The pattern repeats: "if none, return none; if some, unwrap and continue." This is the composition problem — xs[0]? returns Option α, but the next step expects α.

bind (andThen) restores composition:

def andThen (opt : Option α) (next : α → Option β) : Option β :=
  match opt with
  | none => none
  | some x => next x

unit is some — wrap a value, no failure.

Now:

def firstThirdSuccinct (xs : List α) : Option (α × α) :=
  andThen xs[0]? (fun first =>
    andThen xs[2]? (fun third =>
    some (first, third)))

#eval firstThirdSuccinct [1, 2, 3]  -- some (1, 3)

With an infix operator ~~> for andThen, it gets even cleaner:

infixl:55 " ~~> " => andThen

def firstThirdFifthInfix (xs : List α) : Option (α × α × α) :=
  xs[0]? ~~> fun first =>
  xs[2]? ~~> fun third =>
  xs[4]? ~~> fun fifth =>
  some (first, third, fifth)

#eval firstThirdFifthInfix [1, 2, 3, 4, 5]  -- some (1, 3, 5)

2. Except: Error Messages

Except ε α is like Option but carries an error message instead of silent none:

inductive Error (ε : Type) (α : Type) where
  | error : ε → Error ε α
  | ok : α → Error ε α
deriving Repr

Same problem — can't compose because get returns Error String α, not α:

def get (xs : List α) (i : Nat) : Error String α :=
  match xs[i]? with
  | none => Error.error s!"Index {i} not found (maximum is {xs.length - 1})"
  | some x => Error.ok x

bind:

def andThenError (attempt : Error e α) (next : α → Error e β) : Error e β :=
  match attempt with
  | Error.error msg => Error.error msg
  | Error.ok x => next x

unit: Error.ok

Now:

def firstThirdError (xs : List α) : Error String (α × α) :=
  andThenError (get xs 0) fun first =>
    andThenError (get xs 2) fun third =>
    Error.ok (first, third)

#eval firstThirdError [1, 2, 3, 4] -- Error.ok (1, 3)
#eval firstThirdError [1]          -- Error.error "Index 2 not found (maximum is 0)"

3. WithLog: Accumulating a Log

A value paired with accumulated log entries — like the debuggable functions from the Piponi post:

structure WithLog (logged : Type) (α : Type) where
  log : List logged
  val : α
deriving Repr

bind (andThenLog) — run the first computation, then the next, concatenate the logs:

def andThenLog (result : WithLog α β) (next : β → WithLog α γ) : WithLog α γ :=
  let { log := thisOut, val := thisRes } := result
  let { log := nextOut, val := nextRes } := next thisRes
  { log := thisOut ++ nextOut, val := nextRes }

unit (okLog) — wrap a value with an empty log:

def okLog (x : β) : WithLog α β := { log := [], val := x }

Extra operation — save a log entry:

def save (data : α) : WithLog α Unit :=
  { log := [data], val := () }

This is the Writer monad. Compare with the Piponi post: there bind concatenated Strings, here it concatenates Lists. Same idea.

Usage with ~~>L as infix for andThenLog:

def sumAndFindEvens : List Int → WithLog Int Int
  | [] => okLog 0
  | i :: is =>
    (if isEven i then save i else okLog ()) ~~>L fun () =>
    sumAndFindEvens is ~~>L fun sum =>
    okLog (i + sum)

#eval sumAndFindEvens [1, 2, 3, 4, 5]
-- { log := [2, 4], val := 15 }

4. State: Mutable Variables

State is modeled as a function from input state to output state and value — like the random seed example from the Piponi post:

def State (σ : Type) (α : Type) : Type :=
  σ → (σ × α)

bind (andThenState) — thread the state through:

def andThenState (first : State σ α) (next : α → State σ β) : State σ β :=
  fun s =>
    let (s', x) := first s
    next x s'

unit (okState) — return a value, leave the state unchanged:

def okState (x : α) : State σ α :=
  fun s => (s, x)

Extra operations — read and write the state:

def getState : State σ σ :=
  fun s => (s, s)

def setState (s : σ) : State σ Unit :=
  fun _ => (s, ())

Usage — number the nodes of a binary tree with a counter as state, using ~~>S as infix for andThenState:

def numberHelper : BinTree α → State Nat (BinTree (Nat × α))
  | BinTree.leaf => okState BinTree.leaf
  | BinTree.branch left x right =>
    numberHelper left ~~>S fun numberedLeft =>
    getState ~~>S fun n =>
    setState (n + 1) ~~>S fun () =>
    numberHelper right ~~>S fun numberedRight =>
    okState (BinTree.branch numberedLeft (n, x) numberedRight)

def number (t : BinTree α) : BinTree (Nat × α) :=
  (numberHelper t 0).2

#eval number (BinTree.branch
  (BinTree.branch BinTree.leaf "a" BinTree.leaf) "b"
  (BinTree.branch BinTree.leaf "c" BinTree.leaf))
-- branch (branch leaf (0, "a") leaf) (1, "b") (branch leaf (2, "c") leaf)

The Pattern

In the Piponi post we saw three monads:

Type m αbindunitSide effect
Debuggableα × Stringunwrap, apply, concat strings(x, "")debug logging
MultivaluedList αapply to each, flatten[x]multiple values
RandomisedStdGen → α × StdGenthread seed throughfun s => (x, s)randomness

The FP in Lean book gives us four more — all the same structure:

Type m αbindunitSide effect
OptionOption αif none stop, else unwrapsomesilent failure
ExceptError ε αif error stop, else unwrapError.okerror messages
WithLogWithLog logged αrun both, concat logsokLoglogging
Stateσ → σ × αthread state throughokStatemutable state

The triple (m, unit, bind) is a monad:

  • m is the context (failure, error, log, state)
  • unit is the identity (enter the monadic world doing nothing)
  • bind is the composer (chain operations, handling the plumbing)
Terminology

Different sources use different names for the same things:

Our name (Piponi)FP in Lean bookThis postLean's actual API
bindandThenandThen, andThenError, andThenLog, andThenState>>= (or Bind.bind)
unitoksome, Error.ok, okLog, okStatepure (or Pure.pure)

The book uses generic names andThen and ok for all four (in separate namespaces). In our Lean file we use distinct names to avoid conflicts. Lean's Monad type class unifies them all under pure and >>=.
