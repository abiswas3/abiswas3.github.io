A Note On The General Proof Technique

Although we focus on the ADDIW instruction in this post, the general proof outline will hold for all FormatR and FormatI instructions. The crux of the idea is that all these instructions simply read from registers and an intermediate. Reading bits do not change state. After reading values in the source registers, the final outcome is to update a single register rd. No other field in the state machine apart from rd changes. So all the proofs really boil down to, is checking whether the value written to rd is the same, and both the jolt sequence and the original RISCV instruction write the same value register to the same rd.

However, to formally prove two imperative programs are equivalent, we will have to explicitly prove that every field of the state machine and the return values are the same. Given what we said above, this means a lot of the proof will constitute machinery to get rid of the monadic plumbing, saying both LHS and RHS do not touch memory, so they must be equal. It is not interesting, but necessary for correctness. We will try to templatise this and generalise this as much as possible (see below, as to how).

All the real work will happen in a helper lemma with the suffix _concrete in its name. Here we do the main "math" of the proof. The theorem statement will say, look this sequence of jolt instructions only affects register rd. And the value written to rd is exactly the value written by the RISCV instruction. Once we prove this lemma, in the main proof we just substitute this lemma in place of the jolt-update. The net effect is that the main-theorem is a sequence of unfolding the monadic binds and re-writing, with one application of our helper lemma -- and bang the proof passes.

The hope then is for each FormatR and FormatI instruction, we'll just have to write 1 helper lemma, and the rest of the proof machinery, once written will just follow. Whether this approach will fully generalise is still unclear, but it seems to work for the 11 or so instructions we have passing.

We now walk through the proof of jolt_addiw_eq_sail one tactic at a time. At each step, we show the goal before the tactic, the tactic itself, and how the goal changes.

The full proof:

108theorem jolt_addiw_eq_sail (imm : BitVec 12) (rs1 rd : regidx)
109    (hrd : rd ≠ regidx.Regidx 0) (js : SailJoltState) (hwf : WellFormed js) :
110    projectResult ((jolt_addiw imm rs1 rd).run js) =
111    (execute_ADDIW imm rs1 rd).run js.sail := by
112  obtain ⟨js', v1, hj_rx1, hj, hj_sail⟩ :=
113    jolt_addiw_concrete imm rs1 rd hrd js hwf
114  simp only [execute_ADDIW, EStateM.run, bind, EStateM.bind, pure, EStateM.pure, hj_rx1]
115  show projectResult ((jolt_addiw imm rs1 rd).run js) = _
116  rw [hj]
117  simp only [projectResult, project]
118  rw [hj_sail]
119  obtain ⟨s', hw⟩ := wX_shape rd _ js.sail
120  rw [hw]
121  congr 1
122  exact (wX_bits_eq_stateAfterWrite rd _ js.sail s' hw).symm

Step 0: The initial goal

After by, Lean presents us with the goal we need to prove:

⊢ projectResult ((jolt_addiw imm rs1 rd).run js) =
  (execute_ADDIW imm rs1 rd).run js.sail

This is exactly the theorem statement. Now we begin.

Helpers

Before going over every line of the proof, we go over some helper lemmas and definitions that almost every proof re-uses.

stateAfterWrite

In Plain English

stateAfterWrite s rd val returns a new SailState identical to s except that register rd now holds val. It is a specification-level way of describing a register write — without going through the monadic wX_bits. It also guarantees that the only change in state is the write to rd. See wX_bits_eq_stateAfterWrite later.

248noncomputable def stateAfterWrite (s : SailState) (rd : regidx) (val : BitVec 64) : SailState :=
249  { s with regs := wX_update_regs rd val s.regs }

wX_update_regs

wX_update_regs r v regs takes a register index r, a 64-bit value v, and the current register file hash map regs. It inserts v at the Register key corresponding to r. Writing to x0 (index 0) is a no-op — x0 is hardwired to zero in RISC-V.

119noncomputable def wX_update_regs
120    (r : regidx)                                    -- which register to write
121    (v : BitVec 64)                                  -- the value to write
122    (regs : Std.ExtDHashMap Register RegisterType)   -- the current register file
123    : Std.ExtDHashMap Register RegisterType :=       -- returns updated register file
124  match r with
125  | ⟨i⟩ =>                          -- destructure regidx to get the 5-bit index
126    let w := regval_into_reg v       -- convert BitVec 64 to register value type (identity)
127    match i.toNat with               -- match on the natural number index
128    | 0 => regs                      -- x0: no-op, hardwired to zero
129    | 1 => regs.insert Register.x1 w  | 2 => regs.insert Register.x2 w
130    | 3 => regs.insert Register.x3 w  | 4 => regs.insert Register.x4 w
131    | 5 => regs.insert Register.x5 w  | 6 => regs.insert Register.x6 w
132    | 7 => regs.insert Register.x7 w  | 8 => regs.insert Register.x8 w
133    | 9 => regs.insert Register.x9 w  | 10 => regs.insert Register.x10 w
134    | 11 => regs.insert Register.x11 w | 12 => regs.insert Register.x12 w
135    | 13 => regs.insert Register.x13 w | 14 => regs.insert Register.x14 w
136    | 15 => regs.insert Register.x15 w | 16 => regs.insert Register.x16 w
137    | 17 => regs.insert Register.x17 w | 18 => regs.insert Register.x18 w
138    | 19 => regs.insert Register.x19 w | 20 => regs.insert Register.x20 w
139    | 21 => regs.insert Register.x21 w | 22 => regs.insert Register.x22 w
140    | 23 => regs.insert Register.x23 w | 24 => regs.insert Register.x24 w
141    | 25 => regs.insert Register.x25 w | 26 => regs.insert Register.x26 w
142    | 27 => regs.insert Register.x27 w | 28 => regs.insert Register.x28 w
143    | 29 => regs.insert Register.x29 w | 30 => regs.insert Register.x30 w
144    | _ => regs.insert Register.x31 w

Note: _ here works because i comes from a BitVec 5 (via regidx), so i.toNat can only be 0–31. Cases 0–30 are matched explicitly, so _ can only match 31.

wX_shape

wX_shape says that writing to a register via wX_bits always succeeds — for any register r (a bit string of length 5), value v, and state s, there exists a resulting state s' such that wX_bits r v s = .ok () s'.

86theorem wX_shape (r : regidx) (v : BitVec 64) (s : SailState) :
87    ∃ s', wX_bits r v s = .ok () s'

Register writes cannot fail. Unlike readReg (which can throw Error.Unreachable if a key is missing from the hash map), wX_bits always produces an .ok result. This is why we don't need a WellFormed-like precondition for writes.

wX_bits_eq_stateAfterWrite

This lemma connects the monadic wX_bits with the specification-level stateAfterWrite: if wX_bits rd v s = .ok () s', then s' = stateAfterWrite s rd v.

262theorem wX_bits_eq_stateAfterWrite (rd : regidx) (v : BitVec 64) (s s' : SailState)
263    (hw : wX_bits rd v s = .ok () s') :
264    s' = stateAfterWrite s rd v

Running the monadic register write wX_bits produces exactly the same state as the pure stateAfterWrite. This lets us move between the monadic world (used in the actual computation) and the specification world (used in the proof).

jolt_addiw_concrete

This is the main worker lemma. All the heavy lifting happens here.

71theorem jolt_addiw_concrete (imm : BitVec 12) (rs1 rd : regidx)
72    (hrd : rd ≠ regidx.Regidx 0) (js : SailJoltState) (hwf : WellFormed js) :
73    ∃ (js' : SailJoltState) (v1 : BitVec 64),
74      rX_bits rs1 js.sail = .ok v1 js.sail ∧
75      (jolt_addiw imm rs1 rd).run js = .ok RETIRE_SUCCESS js' ∧
76      js'.sail = stateAfterWrite js.sail rd
77        (sign_extend (m := 64)
78          (Sail.BitVec.extractLsb (v1 + sign_extend (m := 64) imm) 31 0))

It says: there exist a final Jolt state js' and a value v1 such that:

  1. Reading succeeds: rX_bits rs1 js.sail = .ok v1 js.sail — reading register rs1 from the initial state returns value v1 without modifying the state.
  2. Execution succeeds: (jolt_addiw imm rs1 rd).run js = .ok RETIRE_SUCCESS js' — running Jolt's ADDIW on the initial state succeeds with RETIRE_SUCCESS and produces final state js'.
  3. The Sail state is characterised: js'.sail = stateAfterWrite js.sail rd (sign_extend (m := 64) (Sail.BitVec.extractLsb (v1 + sign_extend (m := 64) imm) 31 0)) — the Sail component of the final state is the original Sail state with register rd overwritten by sign_extend(extractLsb(v1 + sign_extend(imm), 31, 0)).
Where the real work happens

Let X = sign_extend(extractLsb(v1 + sign_extend(imm), 31, 0)). Note that we know by staring at the execute_ADDIW code that Sail's native execute_ADDIW writes X to rd — this is visible directly from its definition.

But jolt_addiw does two separate steps:

  1. ADDI writes Y = v1 + sign_extend(imm) to rd (the full 64-bit sum)
  2. sign-extend-word reads rd back, gets Y, extracts the lower 32 bits, sign-extends to 64, and writes back

The claim in jolt_addiw_concrete is that after both steps, rd holds X. So we replace Y with X here. When we invoke this in the main theorem, we will observe that all fields of SailState will be definitionally equal.

The Proof

With the helpers defined, we now show how the main proof just decomposes into mechanical unwinding of the monadic machinery.

Step 1: obtain

obtain ⟨js', v1, hj_rx1, hj, hj_sail⟩ :=
    jolt_addiw_concrete imm rs1 rd hrd js hwf

This applies jolt_addiw_concrete (which we just described above) to our hypotheses imm, rs1, rd, hrd, js, and hwf. The result is an existential — obtain destructures it, introducing five new facts into the context:

  • js' : SailJoltState — the final Jolt state after running jolt_addiw
  • v1 : BitVec 64 — the value read from register rs1
  • hj_rx1 : rX_bits rs1 js.sail = .ok v1 js.sail — reading rs1 succeeds
  • hj : (jolt_addiw imm rs1 rd).run js = .ok RETIRE_SUCCESS js' — jolt_addiw succeeds
  • hj_sail : js'.sail = stateAfterWrite js.sail rd (sign_extend ...) — the final Sail state is characterised

The goal does not change:

⊢ projectResult ((jolt_addiw imm rs1 rd).run js) =
  (execute_ADDIW imm rs1 rd).run js.sail

But now we have concrete facts about what both rX_bits rs1 and jolt_addiw compute, which we can use to rewrite both sides.

Step 2: Simplify the RHS

simp only [execute_ADDIW, EStateM.run, bind, EStateM.bind, pure, EStateM.pure, hj_rx1]

This simp only targets the RHS — (execute_ADDIW imm rs1 rd).run js.sail. It:

  1. Unfolds execute_ADDIW — replacing the function name with its body (the do block we walked through earlier).
  2. Unfolds the monadic plumbing — bind, EStateM.bind, pure, EStateM.pure, EStateM.run — turning the do block into concrete function applications on the state.
  3. Rewrites with hj_rx1 — replaces rX_bits rs1 js.sail with .ok v1 js.sail, so the register read becomes a known value.

After this, the RHS is fully evaluated: the monadic chain is gone, v1 is substituted in, and what remains is the concrete result of writing to rd and returning RETIRE_SUCCESS. The LHS is untouched. The goal is now:

⊢ projectResult (jolt_addiw imm rs1 rd js)
  =
  match wX_bits rd (sign_extend (Sail.BitVec.extractLsb (v1 + sign_extend imm) 31 0)) js.sail with
  | EStateM.Result.ok a s => EStateM.Result.ok RETIRE_SUCCESS s
  | EStateM.Result.error e s => EStateM.Result.error e s

The RHS is now a match on the result of wX_bits — if the write succeeds (.ok), return RETIRE_SUCCESS with the new state; if it errors, propagate the error. Next we need to simplify the LHS to match.

Step 3: show + rw [hj]

show projectResult ((jolt_addiw imm rs1 rd).run js) = _
rw [hj]

The simp only in Step 2 unfolded EStateM.run on the LHS, turning (jolt_addiw imm rs1 rd).run js into jolt_addiw imm rs1 rd js (direct function application). The show tactic re-folds this back to the .run form so that it matches the shape of hj : (jolt_addiw imm rs1 rd).run js = .ok RETIRE_SUCCESS js'.

Then rw [hj] replaces (jolt_addiw imm rs1 rd).run js with .ok RETIRE_SUCCESS js' on the LHS. The goal is now:

⊢ projectResult (EStateM.Result.ok RETIRE_SUCCESS js')
  =
  match wX_bits rd (sign_extend (Sail.BitVec.extractLsb (v1 + sign_extend imm) 31 0)) js.sail with
  | EStateM.Result.ok a s => EStateM.Result.ok RETIRE_SUCCESS s
  | EStateM.Result.error e s => EStateM.Result.error e s

The LHS now has a concrete Result value — projectResult applied to .ok RETIRE_SUCCESS js'.

Step 4: simp only [projectResult, project]

simp only [projectResult, project]

Now we unfold projectResult and project on the LHS. projectResult (.ok RETIRE_SUCCESS js') reduces to .ok RETIRE_SUCCESS js'.sail, and project js' reduces to js'.sail. The goal becomes:

⊢ EStateM.Result.ok RETIRE_SUCCESS js'.sail
  =
  match wX_bits rd (sign_extend (Sail.BitVec.extractLsb (v1 + sign_extend imm) 31 0)) js.sail with
  | EStateM.Result.ok a s => EStateM.Result.ok RETIRE_SUCCESS s
  | EStateM.Result.error e s => EStateM.Result.error e s

The LHS is now fully concrete: .ok RETIRE_SUCCESS js'.sail.

Step 5: rw [hj_sail]

rw [hj_sail]

We rewrite js'.sail using hj_sail : js'.sail = stateAfterWrite js.sail rd (sign_extend ...). The goal becomes:

⊢ EStateM.Result.ok RETIRE_SUCCESS
    (stateAfterWrite js.sail rd
      (sign_extend (Sail.BitVec.extractLsb (v1 + sign_extend imm) 31 0)))
  =
  match wX_bits rd (sign_extend (Sail.BitVec.extractLsb (v1 + sign_extend imm) 31 0)) js.sail with
  | EStateM.Result.ok a s => EStateM.Result.ok RETIRE_SUCCESS s
  | EStateM.Result.error e s => EStateM.Result.error e s

The LHS now says: .ok RETIRE_SUCCESS with the state after writing the computed value to rd. The RHS still has the match on wX_bits. We need to collapse that match.

Step 6: obtain ⟨s', hw⟩ := wX_shape rd _ js.sail + rw [hw]

obtain ⟨s', hw⟩ := wX_shape rd _ js.sail
rw [hw]

wX_shape is a lemma that says wX_bits always succeeds: there exists some state s' such that wX_bits rd val js.sail = .ok () s'. The obtain gives us s' and hw : wX_bits rd (...) js.sail = .ok () s'.

Then rw [hw] substitutes this into the RHS match, collapsing it to the .ok branch. The goal becomes:

⊢ EStateM.Result.ok RETIRE_SUCCESS
    (stateAfterWrite js.sail rd
      (sign_extend (Sail.BitVec.extractLsb (v1 + sign_extend imm) 31 0)))
  =
  match EStateM.Result.ok () s' with
  | EStateM.Result.ok a s => EStateM.Result.ok RETIRE_SUCCESS s
  | EStateM.Result.error e s => EStateM.Result.error e s

The match on .ok () s' reduces to .ok RETIRE_SUCCESS s', so the goal is really:

⊢ EStateM.Result.ok RETIRE_SUCCESS
    (stateAfterWrite js.sail rd
      (sign_extend (Sail.BitVec.extractLsb (v1 + sign_extend imm) 31 0)))
  =
  EStateM.Result.ok RETIRE_SUCCESS s'

Step 7: congr 1

congr 1

Both sides are .ok RETIRE_SUCCESS _. The congr 1 tactic says: since the constructors and the first argument (RETIRE_SUCCESS) match, it suffices to show the second arguments are equal. The goal reduces to:

⊢ stateAfterWrite js.sail rd (sign_extend (Sail.BitVec.extractLsb (v1 + sign_extend imm) 31 0)) = s'

Step 8: exact

exact (wX_bits_eq_stateAfterWrite rd _ js.sail s' hw).symm

wX_bits_eq_stateAfterWrite is a lemma that connects wX_bits and stateAfterWrite: if wX_bits rd val s = .ok () s', then s' = stateAfterWrite s rd val. We have hw : wX_bits rd (...) js.sail = .ok () s', so this gives us s' = stateAfterWrite js.sail rd (...). The .symm flips it to stateAfterWrite js.sail rd (...) = s', which is exactly our goal. QED.
