Notation

We use $[n]$ to denote $\{ 1, 2, \ldots, n\}$.

What Is This Course Really About?

A course on Algorithms is really about problem solving. More particularly, it is about understanding how a computer solves problems. Loosely, an algorithm is merely a sequence of instructions that our computer understands and uses to solve the problem at hand.

Let’s make things a little more concrete. Say you arrive at Hyde Park with a map of London’s tube network, and you want to figure out how to get to Richmond Park. This is your problem. You pull out your phone (your pocket-sized computer), type things into Google Maps, and out comes a set of directions. That is our solution. The developers at Google programmed your phone with the Google Maps algorithm that allows you to enter any destination and spits out a route to get there.

As a person trying to understand algorithms, some questions immediately jump out at us.

  1. Did the route actually get us to Richmond, i.e., was the algorithm correct?
  2. Was it sometimes correct and sometimes not, i.e., was randomness used?
  3. Did the algorithm take a long time to give us a correct solution, i.e., is the algorithm efficient?
  4. Is there a better way to get to Richmond, i.e., is this algorithm competitive?

In this course you will play the role of the algorithm designer and answer such questions. Before you can do this, we must first learn how to express these questions in a mathematically precise manner. For that we must understand asymptotic notation.

Asymptotics

In your undergraduate algorithms class, you must have read results saying that the time complexity of finding the largest number in a list of $n$ integers is $O(n)$. Or that finding a path between two nodes in an undirected graph $G=(V,E)$ takes time $O(|V| + 2|E|)$. To communicate the results of any kind of analysis we do in this class, we have to get comfortable with what these statements mean.

Definition — Big O

Let $f, g : \mathbb{N} \to \mathbb{R}_{\ge 0}$. We write $f(n) = O(g(n))$ as $n \to \infty$ if there exist constants $c > 0$ and $n_0 \in \mathbb{N}$ such that, for every $n \ge n_0$,

$$ f(n) \le c g(n). $$

For functions $f, g : (0, \infty) \to \mathbb{R}_{\ge 0}$, we write $f(\varepsilon) = O(g(\varepsilon))$ as $\varepsilon \to 0^+$ if there exist constants $c > 0$ and $\varepsilon_0 > 0$ such that, for every $0 < \varepsilon < \varepsilon_0$,

$$ f(\varepsilon) \le c g(\varepsilon). $$

As an example, consider the sum of the first $n$ natural numbers. We often see the result expressed this way.

\begin{align*} \sum_{i=1}^n i &= n(n+1)/2 \\ &= n^2/2 + n/2 = O(n^2) \end{align*}

Definition — Big Ω

Let $f, g : \mathbb{N} \to \mathbb{R}_{\ge 0}$. We write $f(n) = \Omega(g(n))$ as $n \to \infty$ if there exist constants $c > 0$ and $n_0 \in \mathbb{N}$ such that, for every $n \ge n_0$,

$$ f(n) \ge c g(n). $$

For functions $f, g : (0, \infty) \to \mathbb{R}_{\ge 0}$, we write $f(\varepsilon) = \Omega(g(\varepsilon))$ as $\varepsilon \to 0^+$ if there exist constants $c > 0$ and $\varepsilon_0 > 0$ such that, for every $0 < \varepsilon < \varepsilon_0$,

$$ f(\varepsilon) \ge c g(\varepsilon). $$

The comparison-based sorting example below exemplifies how to use the above definition.

Definition — Little o

Let $f, g : \mathbb{N} \to \mathbb{R}_{\ge 0}$, with $g(n) > 0$ for all sufficiently large $n$. We write $f(n) = o(g(n))$ as $n \to \infty$ if

$$ \lim_{n \to \infty} \frac{f(n)}{g(n)} = 0. $$

Equivalently, for every constant $c > 0$, there exists $n_0 \in \mathbb{N}$ such that, for every $n \ge n_0$,

$$ f(n) < c g(n). $$

Going back to the example of summing $n$ natural numbers, we often write \begin{align*} \sum_{i=1}^n i &= n(n+1)/2 \\ &= n^2/2(1 + o(1)) j \end{align*}

to say $n^2$ is a good approximation of the sum, as the product term goes to 1 when $n$ tends to infinity. We also have the equivalent version for strictly greater than.

Definition — Little ω

Let $f, g : \mathbb{N} \to \mathbb{R}_{\ge 0}$, with $g(n) > 0$ for all sufficiently large $n$. We write $f(n) = \omega(g(n))$ as $n \to \infty$ if

$$ \lim_{n \to \infty} \frac{f(n)}{g(n)} = +\infty. $$

Equivalently, for every constant $c > 0$, there exists $n_0 \in \mathbb{N}$ such that, for every $n \ge n_0$,

$$ f(n) > c g(n). $$

Other Things You Might See

Often you will see people write $f(n) = \operatorname{poly}(n)$. What they mean here is that $f(n) = g(n)^{O(1)}$. Or more simply, $f(n)$ can be expressed as a polynomial in $g(n)$.

Sometimes you will also see people write $f(n) = \widetilde{O}(g(n))$, and what they really mean is $f(n) = g(n)\operatorname{poly}(\log n)$. Intuitively, we are saying $f(n)$ is pretty much $g(n)$ and a little extra, but that little extra is a log factor, so it’s insignificant compared to $g(n)$.

For example, $n^4(\log n)^3 = \widetilde{O}(n^4)$. The tilde lets us hide the logarithmic factor. Note that if you see a tilde, it does not always hide a power of $\log n$. For example, $3^n n^5 = \widetilde{O}(3^n)$, since $\log(3^n) = n \log 3$, so $n^5$ is a polylogarithmic factor in $3^n$.

Models Of Computation

We were deliberately vague about what a computer is earlier. In this course we will discuss 3 models of computation.

  1. The Turing Machine
  2. Circuits
  3. Word RAM model.

To understand why being specific about this matters, we start with a simple problem. Sort a list of $n$ integers? What do you reckon is the sorting time of that algorithm? Again, from your undergraduate years you might remember it is $\Omega( n \log n)$. You might have also seen the following argument. The following definition is from Blum’s lecture notes.

Definition

A comparison-based sorting algorithm takes as input an array $\vec{a} = (a_1, a_2, \ldots, a_n)$ of $n \in \mathbb{N}$ items, and can only gain information about the items by comparing pairs of them. Each comparison (“is $a_i$ > $a_j$?”) returns YES or NO and counts as one time step. The algorithm may also reorder items for free based on the results of comparisons made. In the end, the algorithm must output a permutation of the input in which all items are in sorted order.

So this algorithm does not scan the input values or do anything clever. It decides a sequence of questions it must ask. For example, its first query might be is the item at position 4 smaller than the item in position 9. Based on whether the answer was YES or NO, it might then ask is the item in position 6 smaller than the item in position 9. It goes on asking questions, receiving answers and reordering the input till it outputs a permutation function $\pi : [n] \rightarrow [n]$ that tells us how we can sort the input. A permutation $\pi$ moves the element $a_i$ from position $i$ in the input to position $\pi(i)$ in the final output. Note that the logic for the next question is given by some deterministic function that uses as input the previous questions and previous answers.

Theorem

Any deterministic comparison-based sorting algorithm must perform $\Omega(n\log{}n)$ comparisons to sort $n$ elements in the worst case.

Proof

We want to show that, whatever deterministic comparison-based sorting algorithm we choose, some input forces it to make at least $\log_2(n!)$ comparisons. Fix any such algorithm. Our task is to find an input order $\vec{a} = (a_1, \ldots, a_n)$ that forces this many comparisons.

As we are choosing the input, we can assume that the array $\vec{a} = (a_1, \dots, a_n)$ contains distinct elements. Let $S_n$ denote the set of all permutations $\pi : [n] \to [n]$. A key feature of assuming distinct elements is that every input ordering is sorted by exactly one permutation $\pi \in S_n$. To see why, choose $a_i = \pi(i)$ for each $i \in [n]$. Since the values are distinct, $\pi$ has to be the only permutation that sorts this input. In other words, the map from input orderings to permutations that sort them is a bijective map.

For a comparison query “Is $a_i < a_j$?”, we say that $\pi$ is consistent with the answer if:

  • The answer is YES and $\pi(i) < \pi(j)$; or
  • The answer is NO and $\pi(i) \geq \pi(j)$.

We say $\pi$ is consistent with all $q$ comparison results if the above condition holds for each of the $q$ different comparison queries and its answer.

1

Note that the first query $q_1$ is fixed. We choose $a_1 \in \{\text{YES}, \text{NO}\}$ based on which answer shrinks $H_0$ the least. Then $q_2$ is selected as a deterministic function of $q_1$ and $r_1$. This process goes on $k$ times. $q_k$ is selected as a deterministic function of $(q_1, r_1, \ldots, q_{k-1}, r_{k-1})$.

Set $H_0 := S_n$, the set of all possible sorting permutations. Define $H_q$ to be the set of permutations consistent with the results of all $q \ge 0$ comparisons so far1. The next comparison query $a_i < a_j$ chosen by the sorting algorithm partitions $H_q$ into two sets: those permutations $\pi \in S_n$ for which $\pi(i) < \pi(j)$, and the remaining permutations. Define $H_{q+1}$ to always be the larger of the two sets, breaking ties arbitrarily. If we keep the set where $\pi(i) < \pi(j)$, answer YES to the algorithm’s query; otherwise, answer NO. By a simple counting argument we have $|H_q|/2 \le |H_{q+1}| \le |H_q|$.

Now suppose the algorithm makes $k$ queries and then terminates with output $\sigma$.

As the map from input orderings to permutations is a bijection, for every possible input, there is a unique $\sigma$ it needs to output. From the definition above, the only information the algorithm has to output $\sigma \in S_n$ is the sequence of query-answer pairs it has received in the game above. Recall, for every query we adversarially picked the answer that kept at least half of the permutations consistent with the set of questions and answers so far. Let’s call this adversarial sequence we generated $(q_1, r_1), \ldots, (q_k, r_k)$.

Now we claim that $|H_k| = 1$.

Assume not. Since $H_k$ is nonempty by construction, it contains at least two distinct permutations. We can therefore choose $\pi \in H_k$ with $\pi \neq \sigma$. Observe that $\pi$ is consistent with $(q_1, r_1), \ldots, (q_k, r_k)$. Choose an input $\vec{x}$ by setting $x_i = \pi(i)$ for each $i \in [n]$. Running the algorithm on this input therefore produces the same sequence of queries and answers $(q_1, r_1), \ldots, (q_k, r_k)$ (by consistency and determinism). So the algorithm outputs $\sigma$ as the answer. But the only permutation that sorts this input $\vec{x}$ is $\pi$. Since $\sigma \neq \pi$, the algorithm fails to sort this input, contradicting its correctness. Therefore $|H_k| = 1$.

Let $\pi_*$ be the unique permutation in $H_k$. That is, we choose the input by setting $a_i = \pi_*(i)$ for each $i \in [n]$. Since each query shrinks the size of $H_q$ by at most a factor of 2, we start with $|H_0| = n!$ and reach $|H_k| = 1$ after $k$ queries, so we have

\begin{align*} 1 &\geq \frac{n!}{2^k} \implies k \geq \log_2(n!). \end{align*}

Finally, keep only the largest $\lceil n/2\rceil$ terms in the sum for $\log_2(n!)$. The dropped terms are nonnegative, and each retained term is at least $\log_2(n/2)$. Writing out both steps, for $n \geq 4$, \begin{align*} \log_2(n!) &= \log_2 1 + \log_2 2 + \dots + \log_2 n \\[10pt] &\geq \log_2(\lfloor n/2\rfloor+1) + \dots + \log_2 n \\[10pt] &\geq \underbrace{\log_2(n/2) + \dots + \log_2(n/2)}_{\lceil n/2\rceil\text{ terms}} \\[10pt] &\geq \frac{n}{4}\log_2 n = \Omega(n \log{}n) \end{align*} The last inequality uses $\log_2 n \geq 2$ when $n \geq 4$. Together with $k \geq \log_2(n!)$, this proves $k = \Omega(n\log n)$.

□

But this analysis holds in this weird only comparisons are expensive model. We will actually show that in the model most algorithm designers prefer, which is called the Word-RAM model, the time complexity of sorting $n$ integers is remarkably $O(n)$. But before we get to the Word-RAM model, we start with one of the earliest formal definitions of a computer: the Turing machine.

Turing Machine

This was one of the first models of a computer, and it has been studied extensively in computer science.

Definition — Deterministic $k$-tape Turing machine

Fix $k \ge 1$. A deterministic $k$-tape Turing machine is a tuple

$$ M = (Q, \Sigma, \Gamma, \delta, q_0, q_{\mathrm{acc}}, q_{\mathrm{rej}}), $$

where $Q$ is a finite set of states, $\Sigma$ is a finite input alphabet, and $\Gamma$ is a finite tape alphabet with $\Sigma \subseteq \Gamma$ and a blank symbol $\sqcup \in \Gamma \setminus \Sigma$. The distinct states $q_0, q_{\mathrm{acc}}, q_{\mathrm{rej}} \in Q$ are the start, accept, and reject states. The transition function is

$$ \delta : (Q \setminus \lbrace q_{\mathrm{acc}}, q_{\mathrm{rej}}\rbrace) \times \Gamma^k \to Q \times \Gamma^k \times \lbrace L, S, R\rbrace^k. $$

Each tape has its own read/write head and cells indexed by the integers. On input $w \in \Sigma^*$, tape 1 contains $w$ starting at cell 0 and all other cells are blank; the machine starts in $q_0$ with every head at cell 0. A step reads the $k$ symbols under the heads, changes state, writes one symbol on each tape, and independently moves each head left, stays put, or moves right. Entering $q_{\mathrm{acc}}$ or $q_{\mathrm{rej}}$ halts the machine.

Why Do We Like This Model?

It is extremely unambiguous what the space and time complexities are. It’s quite literally the number of times we invoke the transition function. The space is the total number of cells we used barring the input alphabets.

Why Do We Not Like It So Much?

While it’s really useful for analysing things precisely, it’s also painful in some cases. To demonstrate this, let’s work through the following example. Given a bit string of length $n$, what is the time complexity of deciding whether it is a palindrome? A string is a palindrome if reversing the string does not change the string. For example, 1001 is a palindrome. 1011 is not. From your undergraduate courses, you might claim it’s $\theta(n)$. You could code this problem up in your favourite programming language, and plot the answer for different values of $n$. You might see linear plots.

Now, it is known that for a deterministic one-tape Turing machine, deciding whether a binary string of length $n$ is a palindrome takes $\Omega(n^2)$ transitions in the worst case. This follows from F. C. Hennie’s 1965 crossing-sequence lower-bound work. In Problem Set 1, you will be asked to design a deterministic one-tape Turing machine that decides palindromes in $O(n^2)$ time.

We won’t say too much more about Turing machines till we get to the complexity theory part of the course. For now we will move on to circuits, an equally well studied model of computation.

Word RAM

This model is more akin to a C or assembly program. You have memory where each cell is $w$ bits wide. If $n$ is the size of the problem, e.g., an array of size $n$ with each cell containing a number between 0 and $k-1$, then we normally assume $w \geq \log_2 \max\left\{k+1, n+1\right\}$. This allows us to basically express a pointer to an array location with $w$ bits and index into the addressed store by the pointer in constant time.

The precise definition is quite a mouthful, but it’s given here in the Harvard CS125 lecture notes, Section 6.1 if you are interested.

Roughly, this model says that things for which you have assembly instructions are constant time. Things like

  • Addition and subtraction modulo $2^w$.
  • Left and right shifts.
  • AND, NOT, OR operations.
  • Reading and writing $w$ bits to memory.
  • Testing whether a number is greater than or equal to 0, and so on.

In this course, for the first part at least, we will be using this definition of a computer to do analysis. Take, for example, the following program:

def sum(a : list[int])->int:
    total = 0
    for i in range(len(a)):
        total += a[i]
    return total

Here, it takes $w$ bits to store $i$, so the time is $O(1)$. The total takes $2w$ bits, as the sum can overflow, but that’s $O(1)$. We do $n$ basic operations, so the run time is $O(n)$. The space complexity is $O(1)$, as we do not include the space needed to store $a$ in the analysis.
