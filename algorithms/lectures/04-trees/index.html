The subtree operations:

Traversal orders matter both for the set and sequence interface. For sequences, the order of how things are stored matters. For sets, the traversal order captures the ordering imposed by find_next and find_soft. So we will want to store things in the tree such that when we traverse the tree in order, we will traverse the tree in key order.

So how do we implement find(key) for the set interface.

def find(node, key):
    if node == None:
        return None
    if node.item = key:
        return node 
    elif node.item < key:
        find(node.right, key)
    else 
        find(node.left, key)

Work through a real example in class. Note that we are literally doing binary search, just happens to be doing this on a tree. But what is perhaps a little trickier is to model the sequence interface.

Define size(node) to be the number of nodes in its sub-tree (including itself) Our goal will to be to implement get_at(i) and set_at(i), but this will be easier if we can solve the following general problem.

How do we get the $i$’th node in a subtree?

def subtree_at(node, i):
    nl = size(node)
    if i < nl : subtree_at(node.left, i)
    if i == nl : return node
    # re-indexing go over in class
    if i > nl : subtree_at(node.right, nl - i - 1)

So to insert_at(i) we can just call x=subtree_at(node, i) followed by insert_before(x).

But there is a problem. How do we compute size? If at each step I traversed the sub-tree to get size, then that’s no good. We need to update the size function.

Subtree Augmentation

  • Each node can store a constant number of extra fields, call them properties.

  • Subtree property is something that can be computed from the properties of the nodes children (and node). So for example size is a subtree property because it can be computed as 1 + node.left.size + node.right.size, and i can compute it on constant time.

Note that this property must be downward looking. I cannot look upwards to compute the property of a node.

Now if I want to insert or delete nodes it changes the size of the nodes by adding or removing a leaf in the tree. So I would have to update the field of the ancestors so I can use the sub-tree property. Leaves have no children so their properties can be updated in constant time. But then the parents of those leaves can also be updated in constant time. And there can be at most $O(h)$ parents for any delete or insert.

Remark — Non Subtree property

Index is not a subtree property It is a global property. You might wonder can’t I just store the index of each node as a field? Well when I insert a new node, every node must change its fields, not just the sub-trees. Therefore it’s global not sub-tree.

AVL Trees

Goal of this lecture to ensure that $h = O(\log_2 n)$.

Need some new tools. Rotation – a way to rebalance the tree. We can NEVER change the traversal order. Note the reason we can do this because in a tree there are multiple ways to store the same traversal order. In an array we could not do this. Moreover there is always a balanced tree representing the same traversal order.
