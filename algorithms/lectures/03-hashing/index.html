$\newcommand{\bit}{\{0,1\}}$ $\newcommand{\Universe}{\bit^u}$ $\newcommand{\CompressedUniverse}{\bit^m}$ $\newcommand{\PProb}[2]{\Pr_{ #2}\left[ #1 \right]}$ $\newcommand{\Prob}[1]{\Pr\left[#1\right]}$

Recall the situation we landed ourselves in the last lecture was that we have a universe of $U$ items. However, we only wanted to use $M$ words of memory to store them. We wanted to do so because we wanted to insert $n$ items as per our set interface. Using $U$ cells allowed us to find keys in time $O(1)$, but the find_min and find_next operations now cost us $O(U)$.

As $n \ll U$, a runtime of $O(U)$ is unacceptable. Thus, we want to find some map $h: [U] \rightarrow [M]$ that takes elements $x \in [U]$, and maps them to $h(x) \in [M]$, where $M = \Theta(n)$. This gave us the following picture.

1

Often we will denote a universe element $x \in [U]$ with its binary representation $x \in \bit^u$. Likewise, with mapped elements $h(x) \in \CompressedUniverse$.

We can also safely assume1 that $U$ and $M$ are powers of two, and if they are not we can always pad them the nearest power of two without losing much. So let $U := 2^u$ and $M := 2^m$. Now no matter how we pick this map $h$, by the averaging argument, there is some bucket such that at least $U/M$ universe elements would map to it.

As a result, an adversary who knows $h$ could pick to insert those $n$ universe elements such that they all lead to collisions. And then find will take time $O(n)$. This happens no matter how we pick $h$.

To defend against this attack we will use randomness. We will assume two things.

  1. Our data structure has a tape of random bits. Each bit is unbiased.
  2. The adversary using our data structure does not know the contents of these random bits, and therefore selects the data and the operations independent of this random tape.

Let $\mathcal{H} := \{ h: \bit^u \rightarrow \bit^m \}$ be the set of all functions that map universe elements to the smaller set. We will use our random tape to sample some $h \gets \mathcal{H}$ uniformly at random. As the adversary does not know our random tape, they will not know $h$. Initially we assume that we have no restriction on how many random bits we can use. Given that we can use as much randomness as we desire, the property we want is that each universe element be mapped to a bucket uniformly at random.

That is we want for any $x \in \Universe$ and any $y \in \CompressedUniverse$

$$ \Pr_{h \gets \mathcal{H}}\left[ h(x) = y \right] = \frac{1}{M} $$

You will show in Problem Set 2 that we need $\Theta(U\log_2 M) = \Theta(2^u m)$ random bits to sample $h$ uniformly from all of $\mathcal{H}$.

Now assume we could sample such a $h$. Then what is the expected length of the chain containing $x$ after $n$ inserts?

Let $S \subseteq \Universe$ be the set of $n$ inserted keys, and fix $x \in S$. Let $C_x$ denote the length of the chain of bucket $h(x)$ after $n$ inserts. Let $X_{x,x^\prime} = 1$ if $h(x) = h(x^\prime)$ and 0 otherwise, for $x^\prime \in S$.

\begin{align*} \mathbb{E}[C_x] &= \mathbb{E}\left[\sum_{x^\prime \in S} X_{x,x^\prime}\right] \\[10pt] &= \sum_{x^\prime \in S}\mathbb{E}[X_{x,x^\prime}] \\[10pt] &= 1 + \sum_{x^\prime \in S \setminus \{x\}} \mathbb{E}[X_{x,x^\prime}] \\[10pt] &= 1 + \sum_{x^\prime \in S \setminus \{x\}} \Pr_{h \gets \mathcal{H}}[h(x) = h(x^\prime)] \\[10pt] &\le 1 + \frac{n-1}{M} \\[10pt] &= O(1) \end{align*}

Universal Hash Functions

Notice that the only condition we really needed was the following.

Definition — Universal hashing

Let $\mathcal{H}$ be a nonempty set of functions $h: [U] \rightarrow [M]$. We say that $\mathcal{H}$ is universal if, for any two distinct keys $x,x^\prime \in [U]$,

$$ \Pr_{h \gets \mathcal{H}}[h(x) = h(x^\prime)] \le \frac{1}{M}, $$

where $h$ is sampled uniformly at random from $\mathcal{H}$.

Below is an efficient process by which we can define and sample a hash function from a universal hash family.

View each $x \in \Universe$ as a column vector of $u$ bits. Pick an $m \times u$ matrix $A$ whose entries are independent fair random bits, and define

$$ h_A(x) = Ax \pmod{2}. $$

It is clear that this scheme only needs $um$ bits as opposed to $Um$ bits.

You show in Problem Set 2, Problem 3 that we need far fewer bits to sample a universal hash function than to sample a fully random hash function.

Perfect Hashing

2

Previously we designed what is known as a Monte Carlo styled algorithm. Here the algorithm always terminates. Namely, we can always sample a hash function. It maybe that we get extremely unlucky, and therefore, we have awful performance, but the algorithm to insert keys always terminates.

Universal hashing gives us constant expected lookup time. But there is still a chance that the time complexity to insert $n$ keys into the hash tables results in chains of length $O(n)$, albeit unlikely. Our next challenge is to ask if we can guarantee that this will not happen? We already discussed earlier that we must use randomness. How then we can guarantee that worst case is not too bad? And the answer is that we can, if we are willing to move to a Las Vegas style2 algorithm. What we mean by that is there is a small chance now that our algorithm will never terminate, but when it does we are guaranteed that all operations will be efficient.

For a static set of keys, the idea is to use two levels of hashing to obtain constant worst-case lookup time while still using linear space. This construction is called FKS perfect hashing.

Algorithm

For the remainder of this algorithm we will set $M = n$.

3

If $x$ and $y$ end up in the same bucket we say they collide. When counting collisions, we could say both pairs $(x,y)$ and $(y,x)$ collided. So should we count twice? Here when we say unordered pairs, we count collisions once per pair, no matter the ordering. So we count a collision for either $(x,y)$ or $(y,x)$, but not both.

  1. Sample $h \gets \mathcal{H}$ where $\mathcal{H}$ is a universal family.

  2. Then insert all $n$ keys in $S$. Let $C$ denote the number unordered3 collisions.

  3. If $C \ge n$ then go back to step 1. We will show that on average we will have to back to step one two times.

  4. Now for all the buckets that are occupied with keys, let $L_i$ denote the number of keys in bucket $i \in [n]$. Sample $g_i : [U] \rightarrow [L_i^2]$ from a universal hash family, and send every key $x$ in bucket $i$ to secondary bucket $g_i(x)$. If there is any collision in the secondary layer, sample another $g_i$. Keep trying till no collisions.

Theorem — Static perfect hashing

Let $S \subseteq [U]$ be a fixed set of $n \ge 1$ distinct keys. There is a randomized algorithm that constructs a static dictionary for $S$ with the following guarantees:

  1. The dictionary uses $O(n)$ words of memory.
  2. Every membership query takes $O(1)$ worst-case time and returns the correct answer.
  3. Construction terminates with probability $1$ and takes $O(n)$ expected time.

The construction is Las Vegas: it always produces a correct dictionary when it finishes.

Proof

We use two levels of hashing.

First-level hashing. Sample $h: [U] \to [n]$ uniformly from a universal hash family. For each $i \in [n]$, let $S_i$ be the set of keys in $S$ that map to bucket $i$, and let $L_i = |S_i|$. Every key belongs to exactly one bucket, so

$$ \sum_{i \in [n]} L_i = n. $$

Let $\mathcal{P}$ be the set of unordered pairs $x,y \in S$. There are $|\mathcal{P}| = \binom{n}{2}$ such pairs. For each such pair, let $I_{x,y}$ be 1 if $h(x) = h(y)$ and 0 otherwise. The number of colliding pairs is therefore

$$ C = \sum_{(x,y) \in \mathcal{P}} I_{x,y}. $$

As $I_{x,y}$ is an indicator, $\mathbb{E}_{h}[I_{x,y}] = \PProb{h(x) = h(y)}{h} \le 1/n$. By linearity of expectation,

$$ \begin{aligned} \mathbb{E}[C] &= \mathbb{E}\left[\sum_{(x,y) \in \mathcal{P}} I_{x,y}\right] \\ &= \sum_{(x,y) \in \mathcal{P}} \mathbb{E}[I_{x,y}] \\ &\le \sum_{(x,y) \in \mathcal{P}} \frac{1}{n} \\ &= \binom{n}{2}\frac{1}{n} \\ &= \frac{n(n-1)}{2n} = \frac{n-1}{2}. \end{aligned} $$

We can also count collisions within each bucket. The $L_i$ keys in bucket $i$ contribute exactly $\binom{L_i}{2}$ pairs. Keys in different buckets do not collide, so

$$ C = \sum_{i \in [n]} \binom{L_i}{2}. $$

For each bucket, $2\binom{L_i}{2} = L_i(L_i-1) = L_i^2-L_i$. Rearranging gives $L_i^2 = L_i + 2\binom{L_i}{2}$. Summing over the buckets,

$$ \begin{aligned} \sum_{i \in [n]} L_i^2 &= \sum_{i \in [n]} \left(L_i + 2\binom{L_i}{2}\right) \\ &= \sum_{i \in [n]} L_i + 2\sum_{i \in [n]}\binom{L_i}{2} \\ &= n + 2C. \end{aligned} $$

We keep $h$ if $C \le n$. Otherwise, we sample a new $h$ independently and try again. Since $C$ is nonnegative, Markov’s inequality gives

$$ \Pr[C > n] \le \frac{\mathbb{E}[C]}{n} \le \frac{n-1}{2n} < \frac{1}{2}. $$

Thus an attempt succeeds with probability $p \ge 1/2$. Let $T_0$ be the number of attempts needed, counting the successful attempt. For $t \ge 0$, the event $T_0 > t$ means that the first $t$ attempts all failed. As each attempt uses a fresh independent hash function,

$$ \Pr[T_0 > t] = (1-p)^t \le 2^{-t}. $$

From the definition of expectation, we have $$ \mathbb{E}[T_0] = \sum_{t=0}^{\infty} \Pr[T_0 > t] \le \sum_{t=0}^{\infty} 2^{-t} = \frac{1}{1-1/2} = 2. $$

For every accepted $h$, the bucket sizes satisfy

$$ \sum_{i \in [n]} L_i^2 = n + 2C \le n + 2n = 3n. $$

Second-level hashing. Fix an accepted first-level hash function $h$. The sets $S_i$ and their sizes $L_i$ are now fixed. Skip empty buckets. For each nonempty bucket $i$, allocate a secondary table of size $L_i^2$, and sample $g_i: [U] \to [L_i^2]$ uniformly from a universal hash family.

There are $\binom{L_i}{2}$ pairs of distinct keys in $S_i$. For any one of these pairs, universality gives

$$ \Pr_{g}[g_i(x) = g_i(y) \mid h] \le \frac{1}{L_i^2}. $$

The probability here is over the fresh choice of $g_i$, with $h$ fixed. A collision occurs in the secondary table if at least one of these pairs collides. By the union bound,

$$ \begin{aligned} \Pr[\text{some collision in bucket } i \mid h] &\le \sum_{\substack{x,y \in S_i \\ x<y}} \Pr_{g}[g_i(x) = g_i(y) \mid h] \\ &\le \binom{L_i}{2}\frac{1}{L_i^2} \\ &= \frac{L_i(L_i-1)}{2L_i^2} \\ &= \frac{L_i-1}{2L_i} \\ &< \frac{1}{2}. \end{aligned} $$

If $L_i = 1$, there are no pairs and no collision is possible.

If a secondary table has a collision, clear it, sample a new $g_i$ independently, and try again for that bucket. Once the table has no collisions, keep it and its hash function. Let $T_i$ be the number of attempts needed for this bucket. Conditioned on $h$, the probability of success in each attempt is at least $1/2$. The same calculation as above gives

$$ \Pr[T_i > t \mid h] \le 2^{-t}, \qquad \mathbb{E}[T_i \mid h] = \sum_{t=0}^{\infty} \Pr[T_i > t \mid h] \le 2. $$

Space. The first-level table has $n$ entries. The secondary tables have exactly $\sum_i L_i^2 \le 3n$ cells altogether, so the two levels use at most $4n$ cells. Each occupied secondary cell stores its key, and empty cells are marked empty. Each first-level entry stores the size of its bucket, a pointer to its secondary table, and its secondary hash function. These take $O(1)$ words per entry under our assumptions. The first-level hash function takes another $O(1)$ words. Thus the total space is $O(n)$ words.

K-wise Independent Hashing Functions

There are other types of hash families as well. An extremely popular and useful one that satisfies $k$-wise independence with $2 \le k \le U$. Originally proposed by TODO:, we will see clever uses of these algorithms, we when we go over graph algorithms. Here we will use more randomness than universal functions, but less randomness than the purely random hash function. For now we just introduce the definition.

Definition — K-wise Independent Hashing

A family $\mathcal{H}$ of hash functions mapping $[U]$ to $[M]$ is called $k$-wise-independent if for any $k$ distinct keys $x_1, x_2, \ldots, x_k \in [U]$, and any $k$ values $y_1, \ldots, y_k \in [M]$ (not necessarily distinct), we have

$$ \PProb{h(x_1) = y_1 \land \ldots \land h(x_k) = y_k}{h \gets \mathcal{H}} \le \frac{1}{M^k}$$

If I told you the location of where any $k-1$ distinct keys hashed to, the hashed location of another distinct key would still be uniformly distributed over $[M]$. After revealing the hash values of $k$ distinct keys, $k$-wise independence alone no longer guarantees that another distinct key’s hash value remains uniformly distributed.

The fully random family is $U$-wise independent: the hash values of all $U$ keys are independent and uniformly distributed.
