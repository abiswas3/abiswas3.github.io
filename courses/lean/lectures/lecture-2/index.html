Forward Reasoning : Have

One uses the have tactic, which introduces a new hypothesis. We read have new hypothesis h by apply hq hp.

apply H : H must be a hypothesis or theorem with type P1 -> P2 -> ... -> PN -> Q, where the goal has type Q. This tactic will replace the goal with N separate goals, P1, through PN, as it corresponds to deciding to prove the premises of H and then using it to prove the goal. In the simply case where you just have P -> Q this will replace Q with P.

Since hq : p → q, the goal of is a function expecting a proof of p, and hp : p is exactly that, applying hq to hp produces a proof of q which is my new hypothesis h. In other words, apply reduces the task of finding a proof of q to finding a proof for p, as I have a proof for p, I immediately "have" a proof h for q.

We will start with reasoning with implications in Lean.
-/

/-
**Forwards Reasoning** is reasoning forwards from the hypotheses that other facts must hold.
We can do this with the `have` tactic.
`intro` is used to introduce assumptions.
`exact` or `assumption` can be used to finish the proof.
-/

example (p q r : Prop) (hq : p → q) (hr : p → q → r) : p → r := by {
  intro (hp: p) -- Assume I have p 
  have h := by apply hq hp -- (h:q)
  have h' := by apply hr hp h  -- (h': q->r) at first and then (h': r) 
  exact h'
  }

Forward reasoning starts from what you already know (your hypotheses) and builds towards the goal.

Instead of naming new hypotheses, I can just specialise the existing ones.


/- We can also use `specialize` to apply a hypothesis to arguments. -/
example (p q r : Prop) (hq : p → q) (hr : p → q → r) : p → r := by {
  intro (hp: p) -- Assume I have p 
  specialize hq hp -- I specialise (hq: p->q) to (hq: q) because i give it p 
  specialize hr hp  -- I specialise (hr: p -> q-> r) to (hr: q-> r) because i get it p
  specialize hr hq  -- I specialise (hr: r) to r because i give it q
  exact hr 
}

Backwards Reasoning

Backward reasoning starts from what you need to prove (the goal) and works back towards your hypotheses. You say: "I need s. It suffices to prove r (because hrs : r → s). It suffices to prove q (because hqr : q → r). It suffices to prove p — which I already have." I reduce my goal to p whereas previously, I started with p and found a way to get to the goal.

-- Here we work backwards
example (p q r s : Prop) (hpq : p → q) (hqr : q → r) (hrs : r → s) : p → s := by {
  intro hp
  -- "To prove s, it suffices to prove r" (refine hrs ?_)
  refine hrs ?_
  -- goal: r
  -- "To prove r, it suffices to prove q" (refine hqr ?_)
  refine hqr ?_
  -- goal: q
  -- "To prove q, it suffices to prove p" (refine hpq ?_)
  refine hpq ?_
  -- goal: p
  exact hp
}

Universal Quantifies

The tactics for universal quantification and implication are the same.

  • We can use intro to prove an universal quantification (or implication).
  • We can use apply or specialize to use a hypothesis that is a universal quantification (or implication).

See example below


-- No collisions in the image
def Injective (f : ℝ → ℝ) : Prop := ∀ x y : ℝ, f x = f y → x = y

example (f g : ℝ → ℝ) (hg : Injective g) (hf : Injective f) :
    Injective (g ∘ f) := by {
    unfold Injective at * 
    intro x y h -- The goal is to show P-> Q where P =: f x = f y and Q =: x = y
    -- by intro h we say assume we have P, then we need to show Q
    specialize hf x y 
    specialize hg (f x) (f y) 
    apply hf -- this asks me to now sow that f x = f y  
    apply hg  -- this asks me to show g (f x) = g (f y)
    exact h  -- this is my P
  }
