We start with complexity theory crash course. ## NP Languages

I am using the finitary version of the definition of Languages here. In reality a language is defined asymptotically in terms of n.

Fix arbitrary \(n \in \mathbb{N}\). A language \(L \subseteq \{0, 1\}^{poly(n)}\) is a subset of strings.

Examples + Graphs on n vertices that admit a 3 colouring, where the graph G is represented using using a the \{0 ,1 \}^{poly(n)} encoding. Think adjacency matrix. + Boolean circuits that have at least one input on which it outputs true + Boolean functions where one row of the truth table output is 1.

Thus, a language is a collection strings (or what we call instances later on this document).

\(NP\) is just a set of languages.

Def: NP We say a language L is in NP if there exists a “polynomial-time” deterministic Turing Machine M such that: Fix arbitrary x \in L, there exists w \in \{0 ,1\}^{poly(n)}, such that M(x, y) = 1. + Fix arbitrary x \notin L, for all y \in \{0, 1\}^{*}, M(x, y) = 0.

If L is the set of 3 colourable graphs, and x \in L, then w is the 3 colouring. The algorithm M runs in polynomial time, and on receiving inputs x, y outputs accept. If a graph x was not 3-colourable, there is no colouring that can get M to accept.

Re-writing the above definitions in terms of proofs

So far we have been thinking of w as a witness or a certificate: This is the satisfying assignment for a boolean formula, or the perfect matching in a graph.

Instead we can think of this witness as an object furnished by an external entity called the prover. Then verification can be viewed as a process: On input \(x\), the verifier \(V\) asks to see a proof that \(x \in L\). The prover tries to provide such a proof. If the prover is honest, it will always be able to provide a correct proof (provided it exists). For languages in \(NP\) we know it always exists The verifier should be complete, namely recognize such proofs as correct. On the other hand, if the prover tries to provide a bogus proof (for instance a bad 3 coloring) the verifier should be sound and detect the mistake i.e the proof should be sound.

–Borrowed from Bogdanov’s lectures

So here’s the same \(NP\) definition, described as a proof system.

Def: NP-prover An NP-prover P is any (computationally unbounded) function that maps inputs x ∈ \{0, 1\}^* to proofs \pi \in \{0, 1\}^* . All we mean by computationally unbounded function is that Turing Machine that computes this function can take any number of steps.

Decision Problem: It’s the task of deciding if \(x \in L\) or not.

Def: NP Proof System NP is the class of all decision problems for which there exists a TM - V (called a verifier) whose running time is polynomial in the length of x, and there exists a computationally unbounded function P : \{0,1\}^* \rightarrow \{0,1\}^* (called the honest prover) such that

  • If \(x \in L \implies V(x, \pi) = 1\) where \(\pi = P(x)\)
  • If \(x \notin L \implies V(x, \pi) = 0\) where \(\pi = P^*(x)\) for any \(NP\)-prover \(P^*\).

Interactive Proofs

Now assume that after receiving a proof \(\pi\) from a prover, the verifier is not convinced. This is not a problem for deciding any language in \(NP\). But imagine there exists other languages which are harder to decide. Just a static certificate is not enough. The verifier might want to ask the prover MORE questions. In this setting the prover and verifier are adaptive: The question that the verifier asks at any given round of interaction may depend on the answers it received from the prover in previous rounds. However, the prover himself may choose to adapt his answers based on the previous queries made by the verifier.

To formalise this idea – we introduce the idea of an interactive Turing machine.

This is a Turing Machine that, in addition to its input \(x\), receives additional inputs \((y_1, z_1,\ldots , y_k, z_k)\) which represent the messages sent and received in the first \(k\) rounds of interaction. Here, \((y_1, \ldots , y_k)\) are the messages sent by the machine itself, and \((z_1,\ldots , z_k)\) are the responses received from the other party. On this input, the machine produces the next message \(y_{k+1}\) or possibly accepts/rejects

Let’s say we have machines A and B. They both receive common input x. + A goes first so y_1 = A(x). + B’s turn to respond, with z_1 = B(x, y_1). + Now A could either accept/reject or send message y_2 = A(x, y_1, z_1) to B.

The round complexity of this game/proof system is the number of messages \(A\) sends before outputting accept or reject.

Now the formal definition. We use YES to denote all strings in the language and NO to denote all strings not in language we are trying to decide. We introduce this extra notation, as this plays really well with promise problems. But that’s for later

Def: Deterministic Interactive Proof System A (polynomial-time) deterministic interactive proof for a decision problem (YES, NO) is a pair of Turing Machines (V, P) where V runs in time polynomial in the input x, and + For all x \in YES, (V, P)(x) outputs accepts + For all x \in No, (V, P)(x) outputs reject

So far everything has been deterministic. If the prover is honest, verifier accepts. If the prover cheats, verifier asks it to piss off. If we allow randomness, a magical world opens up.

If we give Turing machines a random tape: simply an infinite array where each location is 1 or 0 with probability 1/2. Then we get the following definition.

[!def] Interactive Proof System >A (polynomial-time) deterministic interactive proof for a decision problem (YES, NO) is a pair of Turing Machines \((V, P)\) where \(V\) runs in time polynomial in the input \(x\), and >+ For all \(x \in YES\), \((V, P)(x)\) outputs accepts with probability at least \(2/3\) >+ For all \(x \in No\), \((V, P)(x)\) outputs accepts with probability at most \(1/3\)

Here is a decision problem that has a two-round interactive proof, but is not (provably) known to be in NP.

Graphs \(G_0\) and \(G_1\) on \(n\) vertices are isomorphic if there exists a permutation \(\pi\) of vertices that, when applied to \(G_0\), outputs exactly \(G_1\), namely

\[(u, v) \in E(G_0) \iff (\pi(u), \pi(v)) \in E(G_1)\] Given a pair of graphs \(G_0\) and \(G_1\) as the problem instance – are they isomorphic?

Arguments Whenever we force the prover to run in poly(|x|) - - the system is called an argument instead of a proof.

Proof Of Knowledge (Is Unrelated To ZK)

Now let’s go back to the example of 3-colouring. Now typically one would hope that the way an NP prover gives a proof that the graph is 3-colourable is by actually knowing a 3 colouring, and thereby using that 3 colouring in some way.

In Zero-Knowledge proofs, the prover is NOT allowed to directly tell me the witness (as I’m not supposed to learn anything more than one exists.) In Succinct Proofs, the prover is NOT allowed to send the whole witness directly. It can send a small fraction of it at best.

Now what I’m about to say might seem bizarre, but we actually do not have a guarantee that the prover that convinces that \(x \in L\) actually knows a witness \(w\) such that \(V(x, w) = 1\).

Here’s a real world example, and then we’ll give a formal example.

Imagine that case of finding the shortest path between city A and city B. You want to give the prover some money, and they’ll tell you the shortest path. But before you pay them, they must prove to you that they actually know the shortest path. A shortest path between cities A and B always exists by definition; but this does not mean that the prover actually knows the path.

Given some \mathbb{G} where discrete log is hard, a generator g and h \in \mathbb{G} as instance, prove that i know w such that g^w = h.

Here is a valid proof – the prover says YES. \(g\) is a generator, therefore for any group element \(h' \in \mathbb{G}\), there exists some \(w'\) such that \(g^{w'} = h'\). As long as \(h \in \mathbb{G}\) – instance \((\mathbb{G}, h, g)\) is in the language. The verifier can check \(h \in \mathbb{G}\) and be done. But the prover did not actually know \(w\). This is a meaningless proof system. We want the prover to prove that it actually knows \(w\).

In many many cases, proof systems that are not proofs of knowledge will use knowledge of the witness. But nothing about the definitions we have used so far, forces it upon the prover to use this knowledge, or prove it had this knowledge.

Knowledge Soundness

Proofs for Knowledge:

Def: A proof system has knowledge soundness with error \kappa if there exists a PPT K s.t for every P^* and every x, if P^* convinces V that x \in L where L is NP, with probability \epsilon > \kappa, then K^{P^*(\cdot)}(x) outputs w s.t (x, w) \in R with probability at least \epsilon(|x|) - \kappa(|x|)

Note that knowledge soundness is a property of how the verifier talks to the prover (in contrast to zero-knowledge which is a property of how the prover talks to the verifier.)

Alternative Formulation It always outputs \(w\) such that \((x,w) \in R\) with probability 1, but the running time is now on \(\frac{poly(\kappa)}{\epsilon - \kappa}\) on average.

One can show the two definitions are equivalent – as long as \(R\) is an NP relation. Original implies alternative: + Run \(K\) many times until a witness is output. Since its an NP relation we can verify the output is correct. As prob of success is \(\epsilon - \kappa\) we will end in \(1/(\epsilon - \kappa)\) tries on average
