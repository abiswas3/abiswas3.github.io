Function Overloading Via Traits

These are notes on how Jolt overrides basic Arkworks functionalities with function overloading. What’s discussed is How arks-bn254::Fr becomes a Jolt field without specifying it to be one. And then when all the code is written as JoltField + Icicle

In field/ark.rs.

impl JoltField for ark_bn254::Fr {const NUM_BYTES: usize = 32;     type SmallValueLookupTables = [Vec<Self>; 2]; }

And as long as this module is part of the crate’s module tree (i.e., you have pub mod field; and pub mod ark; inside field/mod.rs), this implementation becomes globally available to the compiler.

Because in Rust, trait implementations are global.

Therefore in :

use ark_bn254::{Bn254, Fr};
  use ark_serialize::CanonicalSerialize;
  use jolt_core::poly::commitment::hyperkzg::{
      HyperKZG, HyperKZGProverKey, HyperKZGSRS, HyperKZGVerifierKey,
  };
  use jolt_core::poly::multilinear_polynomial::MultilinearPolynomial;
  use jolt_core::utils::transcript::{KeccakTranscript, Transcript};
  use rand_core::SeedableRng;

Although, I never bring in JoltField– ark_bn254::Fr implements Jolt Field because in my module tree aka crate:: there is public field module, which contains the public ark module and their ark_bn254 implements JoltField – It’s a light wrapper.

So how do we tell them not use the Arkworks-msm?

In msm/mod.rs, we find this line

impl<F: JoltField, G: CurveGroup<ScalarField = F> + Icicle> VariableBaseMSM for G {}

is a blanket implementation that says:

Any group type G that: 1. Implements CurveGroup,>
2. Has scalar field F, and 3. Implements the Icicle marker trait,
where F implements JoltField, will now also implement VariableBaseMSM.

In commitment/kzg.rs

use crate::msm::{use_icicle, GpuBaseType, Icicle, VariableBaseMSM};

Now P::G1 does implement CurveGroup; and because in msm/mod.rs we explicitly made every curve group implements trait VariableBaseMSM

Now the line <P::G1 as VariableBaseMSM> forces Rust to use the VariableMSM trait implementation – which is the Jolt implementation. More more details see ``SeeLearningRust/examples function_overloading_via_traits.rs`

let c = <P::G1 as VariableBaseMSM>::msm(
              &pk.g1_powers()[..poly.original_len()],
              pk.gpu_g1().map(|g| &g[..poly.original_len()]),
              poly,
              None,
          )?;

So if a struct X implements traits A, B – and say the struct has method score, and trait A also has method score but different implementation. (X as A)::score uses A’s implementation

Icicle Being Tagged on

Note that we do not use Icicle as a feature, and because of that the compiler runs the follwoing

pub trait Icicle {}
  #[cfg(not(feature = "icicle"))]
  impl<T: ark_ec::short_weierstrass::SWCurveConfig> Icicle
      for ark_ec::short_weierstrass::Projective<T>
  {
  }

Any ark_ec::short_weierstrass::Projective<T> where T: ark_ec::short_weierstrass::SWCurveConfig will also implement icicle.
