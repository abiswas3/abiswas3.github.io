Rust Traits

I think of traits as literal ly what the dictionary meaning of trait is. For example, a person with the overeating trait, eats a lot. In rust language, this person is some struct, who implements the trait overeating. To fulfil the implementation, it must satisfy the social contract of the trait overeating i.e. that is it must implement the method eat_a_lot.

pub struct UnivariateKZG<P: Pairing, G: Group<P> = G1> {
      _phantom: PhantomData<(P, G)>,
  }

Here I have a struct/object called UnivariateKZG which takes aas input two generic types P which implements a Pairing trait. G which implements the Group trait, which takes a generic that implements Pairing. If G is not specified when instantiating the struct – it defaults to G1

Why Use Empty Enums ?

You’re building a generic cryptographic algorithm, like KZG commitments, that can work over: - the G1 group of a pairing (e.g. BLS12-381),
- or the G2 group.

These are different elliptic curves internally — P::G1 and P::G2. You don’t want to write the same code twice:

fn kzg_in_g1(p: P::G1) { ... }
  fn kzg_in_g2(p: P::G2) { ... }

You want to write one function

fn kzg<G: Group<P>>() {
      let x: G::Curve = ...; // Either P::G1 or P::G2
  }

But how do you let the caller choose at compile time whether to use G1 or G2?

You do it with a trait

trait Group<P: Pairing> {
      type Curve;
  }

and marker-types

enum G1 {} // can't be constructed
  enum G2 {}

  impl<P: Pairing> Group<P> for G1 {
      type Curve = P::G1;
  }

  impl<P: Pairing> Group<P> for G2 {
      type Curve = P::G2;
  }

So I’ll never actually physically make G1 with

let x = G1{} // x this will not work

What I am doing is I am creating a type for P::G1 and P::G2 where P is a pairing So now the G1 and G2 are groups, so they have a curve property, and I can access P::G1 or orP::G2 by just referring to G1 or G2.

fn kzg<G: Group<P>, P: Pairing>() {
      let point: G::Curve = ...; // Resolved as P::G1 or P::G2
  }

  // The caller calls kzg using this notation
  // where Bls12_381 is a struct that implements Pairing trait
  kzg::<G1, Bls12_381>(); // G::Curve = Bls12_381::G1

Here is a full working example in learning_rust/examples/empty_enums.rs

use std::marker::PhantomData;

  // Define some fake curve types
  struct Curve1;
  struct Curve2;

  // Trait to represent a "group" selector for some curve type
  trait Group {
      type Curve;
  }

  // Define two zero-sized, uninhabited marker types
  pub enum G1 {} // Uninhabited
  pub enum G2 {} // Also uninhabited

  // Implement Group for the marker types
  impl Group for G1 {
      type Curve = Curve1;
  }

  impl Group for G2 {
      type Curve = Curve2;
  }

  // Generic function that uses the associated type from the Group trait
  fn do_something<G: Group>() {
      // Pretend we "use" the associated type, just printing type names
      println!("Using curve: {}", std::any::type_name::<G::Curve>());
  }

  fn main() {
      // We NEVER construct G1 or G2 — we just use them as type arguments
      do_something::<G1>(); // prints: Using curve: Curve1
      do_something::<G2>(); // prints: Using curve: Curve2
  }
