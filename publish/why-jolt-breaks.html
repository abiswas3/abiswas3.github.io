Why Do We Panic?

When we ran cargo test -p jolt-core -- sha3_e2e_hyperkzg we get the following panic.

thread '<unnamed>' panicked at /Users/aribiswas3/Work-With-A16z/arkworks-algebra/ff/src/fields/models/fp/montgomery_backend.rs:1360:9:
High limb expected to be 0 if S >= 1 before 2p comparison


failures:
    jolt::vm::rv32i_vm::tests::sha3_e2e_hyperkzg

test result: FAILED. 0 passed; 1 failed; 0 ignored; 0 measured; 219 filtered out; finished in 4.79s

This is the code for the Conditional Subtraction for Barrett reduction, that causes the panic! If you look at line 1360, it specifically needs the Big integer listed as r_tmp not have its high bit set to 1. Now when you multiply two numbers, sometimes it may cause the result to cross over the modulus \(p\). In CIOS this is easily resolved by subtracting \(p\) from the product. Which is easily confirmed here, where the __subtract_modulus(a)simply computes \(p-a\) if \(a \ge p\).

fn __subtract_modulus(a: &mut F) {
    if a.is_geq_modulus() {
        __sub_with_borrow(&mut a.0, &#modulus);
    }
}

In Yuval’s new implementation, we find the sometimes the product \(ab\) is two times larger than \(p\), and might require subtracting \(p\) twice. The linked code does not do any subtraction, as this was just benchmarking code.

If we use the linked code directly, the current Arkworks library will sometimes complain at Line 1360 essentially saying the number passed is too big.

Adding this snippet of code to the optimised Montgomery multiplication code resolves this error but at the cost of some performance when compared to the linked code above (we are executing more instructions).

__subtract_modulus(ans)
__subtract_modulus(ans)

In the code for world coin, notice they have a reduce_ct function. This subtracts \(2p\) from \(a\) (the Montgomery product) only if the most significant bit of \(a\) is 1, as described Line

let msb = (a[3] >> 63) & 1;

This appears to be not strong enough of a condition for Arkworks to not complain :-( The remainder of this post discusses why subtracting twice is sufficient.

Why Do The Tests Now Pass

To understand why the tests now pass, we need to first understand how Montgomery multiplication is implemented on computers.

In what follows, we actually describe the Separated Operand Scanning Algorithm (SOS), but deceptively refer to it as the Coarse Integrated Operand Scanning (CIOS) algorithm. This is done for ease of exposition only, the claims would hold regardless.

The CIOS Algorithm

Given a \(n\) limb modulus \(p\), integers \(a\) and \(b\) that are at most \(p-1\), Montgomery multiplication computes

\[ c \equiv abR^{-1} \mod p\]

where \(R=r^n\) and \(r = 2^w\), where \(w\) is the word size (typically 64-bits). To avoid explicitly computing modulo \(p\) by long division, we instead compute \((c + mp)/R \equiv cR^{-1}\mod p\) where \(m\) is an integer such that \(m+cp \equiv 0 \mod R\). A simple calculation solving for \(m\) gives us that \(m = -p^{-1}c \mod R\). For our purposes, \(p\) is prime so \(p\) and \(r\) are co-prime. Therefore, \(-p^{-1}\) is well defined, and thus so is \(m\).

How Is CIOS actually computed

What we describe above is the pseudocode description of the Montgomery reduction algorithm, but in practice we do not actually compute \(m\) as a whole, then multiply it with \(p\) and add it to \(c\). We perform the computation limb by limb.
Borrowing the notation from Yuval’s blog, \(c\) can be written as:

\[ \begin{align} c &\equiv (c_{2n-1} r^{2n-1} + c_{2n-2} r^{2n-2} + \ldots + c_1r + c_0) \mod p \end{align} \]

The limb by limb process follows by repeating the following sub-routine \(n\) times.

Important Sub-Routine

Observe that \(c_0r^{-1} \equiv (c_0 + m_0p)r^{-1} \mod p\) where \(m\) such that \(c_0 + m_0p \equiv 0 \mod r\). Solving for \(m = -p^{-1}c_0 \equiv \mu c_0 \mod r\). Also as we are working modulo \(r\), it suffices to use \(m_{0} = \mu_{0}c_0\) discarding any carries, where \(\mu_{0}\) is the least significant word of \(\mu\).

We overload m a little in notation. This m is NOT the same m as the one defined in the overeall description of the algorithm on top. This m is just to make c0 + mp divisible by r.

Once we compute \(m_0p\), and add this to \(c\) to get \(c^{(1)}\), this should clear the least significant digit based on how we picked \(m\). See below

\[ \begin{align} c &\equiv (c_{2n-1} r^{2n-1} + c_{2n-2} r^{2n-2} + \ldots + c_1r + c_0) \mod p \\[10pt] cr^{-1} &\equiv ( c_{2n-1}r^{2n-1} + c_{2n-2} r^{2n-2} + \ldots + c_1r)r^{-1} + c_0 r^{-1} \mod p \\[10pt] &\equiv ( c_{2n-1}r^{2n-1} + c_{2n-2} r^{2n-2} + \ldots + c_1r)r^{-1} + (c_0+ mp)r^{-1} \mod p \\[10pt] &\equiv (c + m_0p)r^{-1} \\[10pt] &\equiv ( c^{(1)}_{2n-1}r^{2n-1} + \ldots c^{(1)}_1r + 0)r^{-1} \mod p \\[10pt] &\equiv ( c^{(1)}_{2n-1}r^{2n-2} + \ldots c^{(1)}_1) \mod p \\[10pt] \end{align} \]

Repeat The Subroutine \(n\) times

Now we can play the subroutine again with \(c^{(1)}_1\) replacing the role of \(c_0\), and the updated value of \(m = \mu_0c_1^{(1)}\) (NOTE the same \(\mu_0\) is always used)

\[ \begin{align} cr^{-1} &\equiv ( c^{(1)}_{2n-1}r^{2n-2} + \ldots c^{(1)}_1 ) \mod p \\ cr^{-2} &\equiv ( c^{(1)}_{2n-1}r^{2n-3} + \ldots + c_1^{(1)}+ c_1^{(1)}r^{-1} \mod p \\ &\equiv ( c^{(2)}_{2n-1}r^{2n-3} + \ldots + c_1^{(2)} ) \mod p \end{align} \]

In fact we play this game \(n\) times

\[cR^{-1} \equiv cr^{-n} \equiv c^{(n)}_{2n-1}r^{n-1} + c^{(n)}_{n+1}r +c^{(n)}_{n} \mod p\]

To get the final answer.

Why Can’t This Output Be Greater Than \(2p\) ?

What did we actually do in the above process ? Over \(n\) iterations, in each iteration, we added \(m_ip\) to \(c\) and divided by \(r\). More explicitly,

\[ \begin{align} cR^{-1} &\equiv (\ldots((c + m_0p)r^{-1} + m_1p)r^{-1} + \dots + m_{n-1}p)r^{-1} \\[10pt] &= \frac{c + p\sum_{i=0}^{n-1} m_ir^{i}}{r^n} \\ &= \frac{c + mp }{R} \\ &< \frac{Rp + pR}{R}\\ &= 2p \end{align} \]

This is exactly why, if the answer is greater than \(p\), one subtraction suffices. We can verify this here in the current Arkworks implementations.

But when we add one __subtract_modulus after Yuval’s algorithm, and run Jolt tests, Arkworks panics!

To understand why, we first need to understand the new algorithm.

Yuval’s New Multiplication Algorithm

The new algorithm is based on the subtle observation. Quoting the original blog:

Per round of the Montgomery reduction, we previously computed ci(i)r−1 mod  p using n + 1 digit multiplications. An alternative method to achieve this, using only n digit multiplications, is by computing ρ1 = r−1 mod  p. One way to understand this algorithm is that, in each round, the current sum is divided by 𝑟, and the resulting fraction is converted into an n + 1-digit number c̃ρ1, which is then added to the integer part of the division.

In simple words, earlier we were adding and then dividing, now we first divide and then add things!

We start with

\[ c \equiv (c_{2n-1} r^{2n-1} + c_{2n-2} r^{2n-2} + \ldots + c_1r + c_0) \mod p\] Dividing \(c\) with \(r^{n-1}\), we get

\[ \begin{align} cr^{-(n-1)} &\equiv c_{2n-1}r^{n} + \ldots + c_{n-1} + c_{n-2}r^{-1} \ldots + c_1r^{-(n-2)}+ c_0r^{-(n-1)} \mod p \end{align} \]

If we pre-computed \(\rho_i = r^{-i} \mod p\) for all \(i \in [n-1]\), we can re-write the above equation as

\[cr^{-n+1} \equiv \Big(c_{2n-1}r^{n} + \ldots +c_{n-1} \Big) + \Big(c_{n-2}\rho_1\Big) \ldots + \Big(c_1\rho_{n-2}\Big)+ \Big(c_0\rho_{n-1}\Big) \mod p\]

Now each of these bracketed terms are \(n+1\) limbed numbers that were the fractional part of the division (referencing the quoted text) and \(\Big(c_{2n-1}r^{n} + \ldots +c_{n-1} \Big)\) is the integer part of the division – remainder and quotient to be more formal.

These can be calculated independently and in parallel1.

Theorem

Let s = (c2n − 1rn + … + cn − 1) + (cn − 2ρ1)… + (c1ρn − 2) + (c0ρn − 1). We claim that s < n ⋅ (rp).

Dividing \(c\) by \(r^{n-1}\) we get

\[ \begin{align} \frac{c}{r^{n-1}} &= Q + R \end{align} \] where \(R = \Big(c_{n-2}\rho_1\Big) \ldots + \Big(c_1\rho_{n-2}\Big)+ \Big(c_0\rho_{n-1}\Big)\) and \(Q = \Big(c_{2n-1}r^{n} + \ldots +c_{n-1} \Big)\)

Now \(R < (n-1)rp\) as each bracketted term is at most \(rp\).

Also \(Q \le \lfloor \frac{c}{r^{n-1}}\rfloor < \frac{p^2}{r^{n-1}} < \frac{r^np}{r^{n-1}} = rp\)

Therefore, \(Q+R < n\cdot rp\)

Now, the final step of the reduction involves computing \((s + mp)r^{-1}\) where \(m= s_0\mu_0\) and \(s_0\) is the least significant word of \(s\).

From this we can conclude that

\[ cR^{-1} \mod p \equiv (s+ mp)/r < (nrp + rp)/r < (n+1)p\] Therefore, it is often not sufficient to subtract \(p\) from the answer just once. For \(n=4\), this implies that the answer will be less than \(5p\).

So it appears that two _substract_modulus operations were insufficient too, although we were never able to get this to work via fuzzing!
