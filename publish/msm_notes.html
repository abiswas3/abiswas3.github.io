MSM Notes

🧮 Problem Setting: MSM

Given a set of \(n\)-limbed scalars \(\{a_{i}\}_{i=1}^n\) and elliptic curve points over finite field \(F_p\), \(\{P_i\}_{i=1}^n\), the goal is to compute \[ P = \sum_{i=1}^{n} a_{i} P_i\] as fast as possible on a computer.

🚶 Naive Double-and-Add (Per-Point Scalar Multiplication)

For each \(i\):

  • Calculate each \(a_{i}P_i\) using doubling and addition, then add them all together to get the final result. In the worst case, each double and add1 takes \(2\lceil \log_2 |a_i| -1 \rceil\) additions.
  • Cost: \(O(\log |a_i|)\) elliptic curve (EC) operations per scalar (e.g., about 256 if using 256-bit scalars) where \(|x|\) = number of bits needed to represent \(x\).
  • Total cost: \(O(n \log R)\) EC operations (doublings and additions mixed) where \(R=\max_{i \in [n]} 2^{|a_i|}\).

📌 Example:

Say we want to compute \(52P\). As

\[ 52 = 0 \cdot 2^0 + 0 \cdot 2^1 + 1 \cdot 2^2 + 0 \cdot 2^3 + 1 \cdot 2^4 + 1 \cdot 2^5 \]

Bit position (i) Bit value \[2^i \cdot P\] Add to result?
0 0 \[1 \cdot P\] No
1 0 \[2 \cdot P\] No
2 1 \[4 \cdot P\] ✅ Yes
3 0 \[8 \cdot P\] No
4 1 \[16 \cdot P\] ✅ Yes
5 1 \[32 \cdot P\] ✅ Yes

This takes 5 doubling operations to get to \(32P\). In the process we also calculate \(16P\) and \(4P\). And finally 3 additions

🪣 Pippenger’s Algorithm (with window size \(c\))

Core Idea Exploit the structure of many scalar multiplications simultaneously to reduce the number of expensive elliptic curve additions.

Let’s say the scalars are in field \(\mathbb{F}_q\) and the group elements are points on an elliptic curve with base field \(\mathbb{F}_p\).

Let \(C\) the number of bits needed to represent any scalar in \(\mathbb{F_q}\), and \(R=2^C\). Let \(c \in \mathbb{N}\) be the window size. Then any scalar \(x \in \mathbb{F}_q\) can be decomposed into \(m\) digits, each digit a number between \(\{0, \ldots, r-1\}\) where \(r = 2^c\), where \(m = \lceil \frac{W}{c} \rceil\)

\[\vec{x} = x_0 + x_1r + \ldots + x_{m-1}r^{m-1}\]
\(x_i \in \{0, \ldots, r-1\}\) is a \(c\) bit number.

So this means

\[ \begin{align} P &= \sum_{i=0}^{n-1} \vec{x_i}P_i \\ &= \sum_{i=0}^{n-1} (x_{i, 0} + x_{i, 1}r + \ldots + x_{i, m-1}r^{m-1})P_i \\ &= \sum_{i=0}^{n-1}\sum_{j=0}^{m-1}\text{ } x_{i, j}\text{ }r^{j} \text{ }P_i \\ &= \sum_{j=0}^{m-1}r^{j} \sum_{i=0}^{n-1}\text{ } x_{i, j}\text{ } \text{ }P_i \\ &= \sum_{j=0}^{m-1}r^{j} W_j \end{align} \]

where \[ \begin{align} W_j &= \sum_{i=0}^{n-1} x_{i,j} P_i\\ &= \sum_{t=0}^{r-1} t B_t \end{align} \] where \(B_t\) is the sum of all the curve points that need to be added \(t\) times. ### Complexity: this is wrong

  • Number of EC additions/doublings is reduced to:

    \[ O\left(\frac{n}{c} + 2^c\right) \]

    We have \(m = \left\lceil \frac{\log R}{c} \right\rceil\) windows or digits per scalar. For each window do up to \(2^c\) double and adds

wnaf optimisation We can reduce this to 2^{c-1} using signed indices

see more details below.

  • Total complexity:
    \[ O\left( \left( \frac{n}{c} + 2^c \right) \cdot \frac{\log R}{c} \right) \]

  • For optimal \(c \approx \log n\), this becomes substantially faster than the naive method.

📌 Example:

Let’s say:

  • Max number of bits: \(C = 256 = \log R\)
  • Window size \(c = 16\)

Then:

  • Naive: \(O(65536 \cdot 256) \approx 16.7 \times 10^6\) EC operations
  • Pippenger:
    • Windows: \(c = \frac{256}{16} = 16\)
    • Bucket size = \(r= 2^c =2^{16} = 65536\)
    • Total EC operations: roughly \(\left(\frac{65536}{16} + 65536\right) \cdot 16 \approx 6.9 \times 10^5\) EC operations — much smaller

⚖️ Summary Comparison

Feature Naive Double-and-Add Pippenger with Window \(c\)
Time per scalar \(O(\log s)\) \(O\left(\frac{\log s}{c}\right)\) amortized
Total additions \(O(n \log s)\) \(O\left( \left( \frac{n}{c} + 2^c \right) \frac{\log s}{c} \right)\)
Parallelizable No Yes (bucket accumulation is parallelizable)
Memory usage Low Higher (buckets)
Use case Small \(n\), low concurrency Large \(n\), batched MSM

✅ Why Pippenger is Better:

  • Less redundant work: Pippenger combines contributions across scalars at the same window bits, avoiding separate EC operations for each scalar.
  • Better asymptotics: Especially as \(n\) grows large.
  • Highly parallelizable: Modern CPUs/GPUs benefit massively.
